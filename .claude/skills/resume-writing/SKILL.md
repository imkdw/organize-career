# Resume Writing - 이력서/포트폴리오 집필 규칙

## 산출물 2종

| 파일 | 용도 | 형식 |
|---|---|---|
| `output/resume.md` | 경력기술서 원문 (텍스트 재사용/맞춤 조합용) | 마크다운, A4 2~3장 분량 |
| `output/resume.html` | 최종 이력서 (PDF export 대상) | 템플릿 기반 자기완결 단일 HTML |

## resume.md 구조

```markdown
# 경력기술서 - {이름}

## 요약
(3~4문장: 연차, 주력 도메인, 핵심 강점. 숫자 1~2개 포함)

## {회사명} ({YYYY.MM} ~ {YYYY.MM | 재직중}) - {직무}

### {프로젝트/성과 제목}
- (성과 불릿 3~5개)
- 기술: {스택}
```

## 집필 규칙

1. **불릿은 XYZ 공식.** "Z(방법/기술)를 통해 Y(측정치)만큼 X(성과)를 달성" 구조를 기본으로 한다. "결제 시스템 개선" (X) → "세션 상태를 파생 계산에서 명시적 저장으로 재설계하여 정산 불일치 결함 N건 제거" (O). 측정치가 없는 불릿은 넣지 말거나 분석 산출물에서 근거를 더 찾는다.
2. **기능 구현 나열 금지 - 문제 해결 서사로.** "무엇을 만들었다"가 아니라 "어떤 문제가 있었고, 어떤 판단으로, 어떤 결과를 냈다"를 쓴다. 기능 목록은 포트폴리오의 프로젝트 상세에만 허용된다.
3. **기술 선택의 판단 근거를 드러내라.** "소켓 이벤트 파이프라인 구축"보다 "폴링/소켓 방식을 비교 검토하고 실시간성 요구 때문에 소켓을 선택해 구축"이 강하다. 분석 산출물의 트레이드오프 기록(주로 Confluence 설계문서 근거)을 우선 활용한다.
4. **첫 단어는 행동.** 설계했다/구축했다/개선했다/자동화했다. "~에 참여" 금지 - 본인 활동 데이터 기반이므로 주도 표현이 정당하다.
5. **숫자는 분석 산출물의 것만.** 새 숫자를 만들지 않는다. 근거 ID는 resume.md 본문에는 넣지 않고(채용 담당자용 문서) 인벤토리 파일에만 유지한다.
6. **선별 기준 - 임팩트 서열 순.** (1) 비즈니스/사용자 효과가 문서로 확인되는 것 > (2) 설계 판단이 드러나는 것(트레이드오프, 아키텍처 결정) > (3) 엔지니어링 지표(결함 감소, 성능, 자동화) > (4) 규모(이슈/PR 수). 규모만 있는 성과는 요약 섹션의 숫자 카드로 밀어내고 본문 불릿에서는 뺀다. resume.md에는 상위 5~8개만 싣는다.
7. **직무 표기는 데이터 기반으로**: PR의 [BE] 태그 비중 등으로 백엔드/프론트 비중을 판단해 표기한다.
8. **도메인 용어**: franchise = 프랜차이즈, branch = 가맹점 (본부/지점/매장/점포 금지).
9. **금지 표현**: "다양한", "성공적으로", "적극적으로", "약 N건" (정확한 수가 있는데 약을 붙이는 것). "담당했다"/"수행했다" 같은 책임 서술도 성과 서술로 바꾼다. em dash(—) 금지, 가운뎃점(·) 금지.

## resume.html 규칙

- **템플릿을 복사해서 시작한다**: `assets/resume-template.html` → `output/resume.html`. 템플릿의 CSS/구조를 임의로 재설계하지 않는다 (심플 유지가 의도된 디자인).
- **하네스가 채우는 곳은 `AUTO:PROJECTS` 섹션뿐이다.** 템플릿 주석에 명시된 item 반복 구조를 그대로 사용해 프로젝트를 임팩트 서열 순으로 채운다.
- **소개/업무경험/학력/자격증은 직접 작성 영역** - `todo` 플레이스홀더를 유지하고 내용을 창작하지 않는다. 단, 업무경험의 회사명/기간/직무 뼈대는 데이터에서 확인되면 채워도 된다.
- 자기완결: 외부 폰트/스크립트/이미지 금지. 시스템 폰트 스택 사용.
- 이름/이메일 등 `{{...}}` 토큰은 알고 있는 값(git config, env)만 채우고 나머지는 토큰 그대로 둔다.

## PDF export

인쇄 CSS(A4, `todo` 박스 자동 숨김)가 템플릿에 내장돼 있다. 두 가지 방법:

```bash
# headless Chrome (권장)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --print-to-pdf=output/resume.pdf --no-pdf-header-footer output/resume.html
```

또는 브라우저에서 열어 인쇄 → PDF 저장. 사용자가 "PDF로 뽑아줘" 하면 위 명령을 실행한다.

## 인벤토리 파일

`_workspace/draft/03_writer_inventory.md`에 전체 성과 단위를 근거 ID 포함으로 보존한다. resume.md에서 뺀 것도 전부 - 면접 예상 질문 대비, 다른 회사 맞춤 이력서 재조합의 원천이다. 각 성과에 `[채택]` / `[미채택: 사유]`를 표기한다.
